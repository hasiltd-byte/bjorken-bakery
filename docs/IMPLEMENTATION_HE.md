# ביורקן — מסירת Preview מקומי

**עדכון תשתית:** האתר חובר ל־Atlas במסד `bjorken_dev`; ההוראות על מסד מקומי בהמשך מתארות את שלב ה־Preview הראשוני. להפעלה העדכנית, העברת הנתונים ובדיקות חיבור ראו [חיבור Atlas](ATLAS_HE.md). משתמשים כעת ב־`npm start` או `npm run dev` עם `.env`.

נבנה ב־22.10.2026 עבור בקשות איסוף ביום שישי 23.10.2026. האתר נשאר Preview; לא פורסם אתר ציבורי ולא נשלחו הודעות.

## המקור שאותר ומה ממוחזר

המקור המלא נמצא ב־`C:\Users\admin\Desktop\sites-ai\cotta-nextjs\cotta-nextjs`, גם לפי תיקיות העבודה האחרונות של VS Code. לא נעשה שימוש ב־ZIP הישן ולא שונו קובצי קוטה. לא הועתקו `.env`, משתמשים, סיסמאות, מסדי נתונים או הזמנות.

מיפוי קוטה: Next.js App Router, React ו־TypeScript; תפריט משותף; `/order/[[...path]]` עם מתאם Web Request; שירות הזמנות MongoDB/Mongoose עם replica set, טרנזקציות ונעילת כתיבות; StaffSession עם תפוגה; ניהול `/admin/menu`; CRUD עם revision למניעת דריסת עריכות; העלאת תמונות ב־sharp ושמירתן ב־GridFS; סל ומסכי takeaway בקוד `orders-app/public/app.js`; קוד הזמנות ושולחנות משולב; Docker וסקריפטי build ובדיקות. כתובות הרפרנס החיות לא היו נגישות בכלי הגלישה; הקוד המקומי הוא בסיס העבודה המאומת.

מוחזר ומותאם:

- `orders-app/database.mjs` ← `lib/server/database.mjs`: חיבור MongoDB, פעולות נתונים, נעילת כתיבות, טרנזקציות ו־GridFS. הוסרו אתחול שולחנות ומודלי מסעדה ונוספה הגבלת שם מסד ל־`bjorken` או `bjorken_test`.
- `orders-app/products.mjs` ← `lib/server/products.mjs`: CRUD, בדיקות שדות, revision, soft delete וצינור העלאת תמונה. נוספו מחיר nullable, מבצע, מלאי, מגבלת כמות, הסתרה וקוד פנימי.
- `app/admin/menu/MenuManager.tsx` וה־CSS ← אותם נתיבים בביורקן: עורך המוצרים, תמונות, חיפוש, סינון, טפסים במובייל. הותאמו קטגוריות ו־Preview; פעולה רגילה מסתירה ומחזירה מוצר במקום למחוק.
- טעינת הגדרות נעשית ישירות על ידי Next.js מקובץ `.env.local` או מסביבת הפריסה. אין טוען סביבה מותאם או שרת backend נפרד.

נכתבו לביורקן: העיצוב הציבורי והסל ב־`app/Bakery.tsx`; מדיניות מחיר ואישורי פתיחה; סכמות מאפייה ללא שולחנות; API בקשות, אימות חדש לפי דפוס sessions של קוטה, מסך הגדרות ובקשות, סקריפט הפעלה ובדיקות. זרימת קוטה הכוללת סועדים/תשלום/מחיר חובה לא הועתקה כפי שהיא, משום שבביורקן בקשה ללא מחיר דורשת טיפול שונה.

## הפעלה וכניסת מנהל

אפשר לפתוח `START-BJORKEN.cmd`, או להריץ בתיקיית הפרויקט:

```powershell
npm.cmd install
npm.cmd run build
npm.cmd run preview:local
```

אתר: http://localhost:3030 · מנהל: http://localhost:3030/admin · מוצרים: http://localhost:3030/admin/menu

בהפעלה הראשונה נוצר שם משתמש וסיסמה אקראית חדשה. הפרטים נמצאים ב־`.local/ADMIN_ACCESS.txt`. זה קובץ מקומי פרטי שאינו נכלל בפרסום או ב־Git. אין סיסמת ברירת מחדל. לא לשתף את קובץ הפרטים או את תיקיית `.local`.

לעדכון מוצר: כניסה למנהל → מוצרים, מחירים ותמונות → עריכת מוצר → שינוי פרטים → שמירה → רענון האתר הציבורי. מחיר ריק פירושו ״מחיר באישור המאפייה״. אפס אינו מחיר מותר. ניתן להוסיף מוצר עם תמונה, להעלות צילום מהמכשיר, להגדיר מלאי ומגבלת כמות ולהסתיר או להחזיר מוצר. הקטגוריות הראשוניות מוגדרות בקוד; יצירת קטגוריה חדשה אינה כלולה בעורך הנוכחי.

בהגדרות העסק ניתן לערוך טקסטים, תמונה ראשית באמצעות נתיב תמונה שהועלתה, WhatsApp, טלפון, כתובת וקישורים, שעות, תאריך וחלונות איסוף, מכסה, מועד סגירה והסכמות. שינוי מספר WhatsApp מבטל את האימות הקודם, ולכן שומרים מספר ורק לאחר בדיקתו מאשרים שוב. אימות המספר הוא אישור ידני של המנהל אחרי ניסיון אמיתי; לא נבנתה מערכת OTP או WhatsApp Business API.

## מה עובד בפועל

- אתר RTL מותאם מובייל, תמונות WebP שסופקו, סינון קטגוריות, סל מקומי ושמירתו באותו דפדפן.
- checkout עם שם, טלפון, תאריך, שעת איסוף, הערה, אישור תנאים ובדיקה לפני שליחה.
- מחיר חסר אינו הופך לאפס; מוצג רק סיכום חלקי כשיש תערובת מחירים. אין סליקה.
- ניהול אמיתי המאומת בשרת; מוצרים, תמונות והגדרות נשמרים ב־MongoDB ונקראים מחדש על ידי משתמשים אחרים. אין localStorage לנתוני העסק.
- סביבת ההפעלה המקומית מפעילה MongoDB replica set של פיתוח עם קבצי נתונים בדיסק בתוך `.local/mongo`. זו סביבת בדיקה מקומית, ללא חשבון Atlas וללא שירות אירוח.
- API בקשות אמיתי, אך חסום במצב Preview. בפתיחה מורשית בלבד: שמירת `pending_confirmation`, מניעת כפילויות לפי nonce, בדיקת מחיר וכמות בשרת, מכסה וניכוי מלאי בטרנזקציה. בקשה ממתינה שומרת מלאי; ביטול/דחייה משחררים אותו. אין שחרור אוטומטי, ולכן המנהל צריך לטפל בבקשות שלא הושלמו ב־WhatsApp.
- קידום סטטוס דורש אישור מחיר וזמינות מול הלקוח. תשלום מסומן רק ״באיסוף״, ללא מצג ששולם. תור המנהל מוגבל ל־500 בקשות אחרונות וכולל חיפוש וסיכום כמויות.
- קישור WhatsApp מכין הודעה; הלקוח נדרש ללחוץ Send בתוך WhatsApp. אין אישור מסירה או אישור הזמנה בעקבות פתיחת קישור. ב־Preview רואים נוסח בלבד, ללא שמירה וללא קישור WhatsApp.
- הגנות: session אקראי עם HttpOnly ו־SameSite, תפוגה, בדיקות מקור בקשות, הרשאת מנהל בצד שרת, בדיקות קלט, הגבלת ניסיונות, מניעת דריסת עריכה ו־noindex. הגבלת הקצב הנוכחית היא לכל תהליך שרת; פריסה מרובת מופעים תדרוש הגבלה משותפת בשכבת האירוח או במסד.

התפריט והתמונות הם תוכן ראשוני לאישור. אין התחייבות שמשקל, רכיבים או אלרגנים ידועים; פרטים כאלה לא הומצאו. שמות קטגוריות קבועים, גלריה מרובת תמונות, התראות אוטומטיות ומערכת משתמשים מרובת תפקידים אינם כלולים. יש מנהל עסק אחד דרך פרטי שרת ייעודיים.

## בדיקות

```powershell

npm.cmd test
npm.cmd run test:browser
```

בדיקות השרת רצות עם replica set מבודד ללא שימוש ב־MONGO_URI של משתמש. מכסות כניסה, הרשאות, CRUD, מחיר חסר ואפס, תמונות, הסתרה/החזרה, עימות גרסאות, persistence לאחר חיבור מחדש, מניעת זיוף מקור, פתיחה/סגירה, ישראל, בקשות מקבילות מול יחידת מלאי אחת, כפילויות, סטטוסים והחזרת מלאי.

בדיקות הדפדפן משתמשות ב־Chrome המקומי ובמסד בדיקות אחר, בפורט 3031. מכסות שולחן עבודה, רוחבי 360/390/430, סל ו־checkout, הודעת Preview, חסימת WhatsApp, ניהול מוצרים כולל תמונה ושינויים באתר, הסתרה/החזרה, מחיר ריק, הגדרות העסק, שמירת מספר WhatsApp ועורך במובייל. צילומי מסך נמצאים ב־`.qa/screenshots`.

כל הבדיקות לעיל עברו בפועל. נבדקה בנוסף עצירה והפעלה מחדש מלאה של שרת Next.js ושל MongoDB המקומי; שינוי בהגדרות נשמר ופרטי המנהל המשיכו לעבוד. במהלך הבדיקה תוקנו יציבות כתובת חבר ה־replica set המקומי ובדיקת המקור עבור localhost/127.0.0.1. הגדרות התפריט הוחזרו למצב הראשוני לאחר בדיקת ההתמדה.

## לפני אתר חי

1. **אישור בעל העסק ומספר WhatsApp:** לבדוק בעלות ונייד תקין, לקבל אישור לפתיחת בקשות ולבצע ניסיון מלא עד קבלת ההודעה בצד העסק. לא בוצע ניסיון אמיתי משום שלא סופק מספר מאומת.
2. **תפריט ותפעול:** לאשר שמות, צילומים מול מוצרים, זמינות ומלאי, מחירים או מדיניות אישור מחיר, שעות, חלונות איסוף 23.10.2026 ומועד סגירה. לאשר פרטי מיקום וטלפון. אחרי שהתאריך חולף האתר חוסם בקשה עד לעדכון מועד במנהל.
3. **תמונות ותשתית:** לקבל רשות שימוש מהבעלים ועדיף תמונות מקור. להגדיר חשבון אירוח, מסד MongoDB replica set מתמשך ונפרד עם משתמש שמורשה רק לביורקן, סיסמת מנהל ייעודית, HTTPS, גיבויים ואבטחת פריסת Preview. לא להעלות את מסד הפיתוח או פרטי הגישה המקומיים. DNS ל־`bjorken.mybizsite.co` יוגדר רק בחשבון המורשה ואחרי אישור.

לפריסה: משתני השרת מפורטים ב־`.env.example`; מסד בשם `bjorken`. בפריסת Preview משאירים `BJORKEN_ENABLE_LIVE=false`. פתיחה אמיתית דורשת שינוי שרת מפורש ל־`true` **וגם** כל אישורי המנהל, מספר מאומת, הזמנות פתוחות ותאריך תקין. אין צורך להכניס סוד לקוד הלקוח. `X-Robots-Tag` ו־robots נשארים noindex בפרויקט הנמסר; בהשקה ציבורית מאושרת יש להגדיר דומיין/canonical/OG סופיים ולשנות מדיניות אינדוקס. לא נוצר קישור Preview חיצוני מפני שלא חובר חשבון פריסה ולא ניתן אישור לפרסום בשם העסק.
