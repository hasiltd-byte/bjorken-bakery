# דו״ח פיילוט ביורקן — 24.10.2026

בוצע בענף `feature/bjorken-hasi-pilot` על בסיס האתר הקיים. אתר HASI הראשי, Cotta, `/miluim` ותהליכי מכירת אתרים לא שונו. לא בוצע Deploy, לא נזרעו נתוני דמו ב־Atlas ולא הופעלו הודעות או חיובים אמיתיים.

## שלב 0 — בדיקה ובסיס

ה־audit זיהה חנות ומנהל אמיתיים, MongoDB, Cloudinary, הזמנות/מלאי אטומיים וסטטוסים. נוספו registry לרישוי, namespace נפרד לדמו, הרשאות עובדים בצד השרת, audit ו־adapters לספקים. חשבון owner קיים נשמר; משתמשי צוות חדשים נוצרים רק בפעולה מפורשת, מחוץ למצב דמו. השבתת עובד מנתקת את ההתחברויות שלו.

## שלב 1 — חנות ו־PWA

נשמרו שלושת העיצובים וכל הזרימות הקיימות. נוספה אפשרות משלוח רגיל בתיאום, כבויה כברירת מחדל, עם כתובת חובה ודמי משלוח ממקור שרת. נוספו manifest, אייקונים 192/512 ו־maskable, הוראות Android/iPhone, שיתוף ו־QR אמיתי שמיוצר מקומית. ה־service worker שומר רק אייקונים ודף ניתוק, לא API או פרטים אישיים. בדיקת offline אמיתית בדפדפן עברה. התקנה פיזית במכשירים וב־HTTPS עדיין דורשת בדיקת קבלה לפני rollout.

## שלב 2 — הזמנות, מוכר ואופה

נבנו מסכי הזמנות וייצור עם polling כל חמש שניות, ספירת מלאי מוכן, כמויות שמורות כולל משלוחים קבוצתיים, אצוות בהכנה/בתנור, מעבר חד־פעמי למלאי מוכן והתראות חוסר ידניות. לאופה מוסתרים שדות קשר, כתובת, מחירי פריטים ותשלום. מעקב לקוח מוגן בטוקן מציג רק אירועים שנשמרו; הקישור נכלל בבקשת ה־WhatsApp ונשאר פתוח גם אם רישיון המודול פג. אימות תשלום ידני רגיל דורש סכום ואסמכתא. אין כאן מתכונים, חישוב חומרי גלם, קופה פיסקלית או הבטחת זמני הגעה.

## שלב 3 — משלוחים קבוצתיים

נבנו מסלולים מרובי נקודות, מועד סגירה, מינימום אישי, ספים פנימיים, דמי משלוח אישיים ידועים/מרביים ומדיניות מסירה. המידע הציבורי אינו כולל מחזור, יעד קבוצתי או רווחיות. הבקשה ממתינה לאימות תשלום; מלאי נשמר רק לאחר אימות מורשה. מסירה דורשת קוד אישי, ומורשה איסוף נתמך. קיימים אי־איסוף, החזרה עם הערת בטיחות, תיאום איסוף מאוחר/משלוח חוזר בהסכמה, תזכורת WhatsApp ידנית ומחשבון מנהל לפי נתונים ידניים. זיכויים ממתינים לתיעוד החזר בפועל, עם מניעת כפל וגבול הסכום ששולם. אין PSP או החזר אוטומטי פעיל.

## שלב 4 — מועדון, ביקורות ודוחות

הרשמה כוללת הסכמה שיווקית נפרדת ולא מסומנת מראש, יום הולדת אופציונלי, מניעת כפילות וקישור ניהול אישי. הסרה נשארת זמינה גם אחרי פקיעת רישיון. קופונים נבדקים ונצרכים אטומית בחנות, עם תוקף, מינימום ומכסת שימושים; הם אינם חלים על מחירים לא ידועים. נוספו מבצעים, משוב טקסטואלי בהרשאת פרסום ומודרציה לכל דירוג, וקישור Google משותף לכל המשתמשים. דוחות יומיים/חודשיים מפרידים שווי בקשות מתקבולים ידניים מאומתים ומציגים אומדני עלות בלבד. אין שליחת Push/דיוור המוני, העלאת מדיה לביקורת או רווח נקי מחושב.

## תוצאות בדיקה

- `npm test`: **15 בדיקות עברו**. כוללות בדיקות אינטגרציה מרובות תרחישים: הרשאות, פקיעה, הפרדת דמו/עסק, מלאי מקבילי, אצווה חד־פעמית, קופון מוגבל במקביל, קודי מסירה, חסימת תשלום לא מאומת, זיכוי כפול/חורג, הסרה, פרטיות מעקב ובטיחות cache.
- `npm run build`: **עבר**, כולל TypeScript וכל הנתיבים החדשים.
- `npm run test:browser`: **עבר**, כולל החנות המקורית ושתי חלופות העיצוב, CMS, סל, מחירים חסרים, WhatsApp מיורט, אירועים, מפה ואנשי קשר.
- `npm run test:pilot`: **עבר**, כולל יצירת מסלול בממשק, הזמנת לקוח, אימות תשלום סימולטיבי, מסירה בקוד, מועדון והסרה, דוחות, manifest/QR, service worker וניתוק רשת אמיתי. בדיקות תצוגה ב־320–1440 פיקסלים עברו.

צילומי בדיקה מקומיים: `.qa/pilot/food-mobile.png`, `orders-mobile.png`, `group-tracking.png`, `install.png`. אלה אינם קישורים להזמנות אמיתיות.

## איך לבדוק עכשיו

1. `npm run preview:pilot` — MongoDB מקומי מתמשך ונפרד, ללא חיבור ל־Atlas. ההרצה האחרונה נשארה בפורט 3030.
2. פתחו `http://localhost:3030/admin/modules` והתחברו עם פרטי המנהל המקומיים הקיימים.
3. בחרו **הדגמה מבודדת**, ואז מסך מוכר ואופה / הזמנות / משלוחים / מועדון / משוב / דוחות. נתוני העסק הרגילים אינם מוחלפים.
4. `http://localhost:3030/install` מציג התקנה ושיתוף. באתר הציבורי החדש מופיע קישור לכך בתחתית.
